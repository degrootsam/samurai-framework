# Continuous integration — design

Date: 2026-10-01
Status: approved design, not implemented
Branch: `ci/github-actions`, based on `feat/test-api-alignment` (PR #6)
Depends on: PR #6 (on `main` today, `tsc` reports errors and every browser test fails on Firefox 157's privileged `about:home`)

## Goal

Every push to `main` and every pull request runs the typecheck, the unit tests and the browser tests on GitHub Actions, using bun.

## Non-goals

- Linting (ESLint) and format checks (Prettier): not wanted for now.
- A macOS or Windows runner. Linux finds the same protocol bugs at a tenth of the macOS minutes.
- Test coverage reports, caching tuned beyond what `setup-bun` does, release or publish jobs.
- Pinning the Firefox version (see Risks).

## Decisions

- **bun, not npm.** `bun install --frozen-lockfile` and `bun run <script>`; `bunx` for one-off binaries. The package scripts are unchanged: `bun run test` still runs `tsx --test` on Node's test runner. CI does not switch to `bun test`.
- **Node is still installed.** The scripts run `tsx`, which runs on Node, and the runner uses `fs/promises` `glob` (Node 22+). CI pins Node 26, the version the code is developed against.
- **Three parallel jobs** instead of one job with three steps: a failure names the broken check, and the checks don't wait on each other.

## Workflow — `.github/workflows/ci.yml`

### Triggers

```yaml
on:
  push:
    branches: [main]
  pull_request:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read
```

A new push to a branch cancels that branch's run in progress. The workflow only reads the repository.

### Shared setup (every job)

1. `actions/checkout@v4`
2. `oven-sh/setup-bun@v2` with `bun-version: 1.3.0` (the local version)
3. `actions/setup-node@v4` with `node-version: 26`
4. `bun install --frozen-lockfile` — fails when `bun.lock` and `package.json` disagree

Each job runs on `ubuntu-latest`.

### Jobs

| Job id      | Name                    | Command                                          | `timeout-minutes` |
| ----------- | ----------------------- | ------------------------------------------------ | ----------------- |
| `typecheck` | Typecheck               | `bunx tsc --noEmit -p .`                         | 5                 |
| `unit`      | Unit tests              | `bun run test`                                   | 10                |
| `browser`   | Browser tests (Firefox) | `firefox --version`, then `bun run test:browser` | 15                |

- The browser job uses the Firefox preinstalled on `ubuntu-latest`; the framework finds it with `which firefox`.
- `firefox --version` is its own step so the log shows which Firefox ran.
- `timeout-minutes` stops a hung browser run instead of holding a runner for the default 6 hours.

### When a job fails

The browser job uploads the framework's logs and the report:

```yaml
- if: failure()
  uses: actions/upload-artifact@v4
  with:
    name: browser-test-logs
    path: |
      logs/
      result/
    retention-days: 7
    if-no-files-found: ignore
```

`logs/combined.log` holds the BiDi traffic, which is how browser failures are diagnosed. Test secrets in CI are fake values, and the logger masks registered secrets.

## Risks

- **Firefox version drift.** `ubuntu-latest` installs Firefox from a PPA; its version can differ from the local Firefox 157, so a browser test can pass locally and fail in CI or the reverse. Mitigation: the version is logged; if a version-specific failure appears, pin it with `browser-actions/setup-firefox` in a follow-up.
- **Headless Firefox on Linux** has no display; the browser tests already launch with `headless: true`.

## Verification

- `ci.yml` is valid YAML and passes `actionlint` (run with `bunx` or the `rhysd/actionlint` Docker image if available locally; otherwise the first GitHub run is the check).
- The commands each job runs pass locally with bun: `bun install --frozen-lockfile`, `bunx tsc --noEmit -p .`, `bun run test`, `bun run test:browser`.
- After pushing the branch and opening a PR against `feat/test-api-alignment`, all three jobs are green on GitHub. A failing check is diagnosed from the run log (and the artifact for the browser job), not guessed.
